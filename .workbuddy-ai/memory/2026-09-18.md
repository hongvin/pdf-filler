## Architecture decisions

- **No framework, no bundler.** Plain ES modules in `public/lib/`, vendored
  pdf.js / pdf-lib / fontkit. Avoids the sandbox `mkdir` broker problem
  entirely (see the `cloudflare-pages-deploy-from-workbuddy` skill) — nothing
  needs `npm install` or `next build` to ship.
- **Client-side filling.** The PDF never leaves the browser. The only server
  call is `/api/config`, which exists solely so the IC number is not compiled
  into the JS bundle.
- **Access gate on by default.** `functions/_middleware.js` puts HTTP Basic auth
  in front of everything when `APP_PASSWORD` is set, and *fails closed* — if
  `APP_PASSWORD` is unset, `/api/*` returns 503 rather than serving the IC.
  Verified: `/` → 401, `/api/config` → 401, with credentials → 200.
- **`public/lib/` is shared with Node.** The test harness in `tools/test.mjs`
  imports the exact same modules, which is why the detection logic could be
  verified headlessly before any UI existed.

## Things that cost time (all documented in code comments)

1. **pdf-lib's font subsetter corrupts Great Vibes.** `subset: true` renders
   "HongVin" as two stray marks. `subset: false` renders correctly. Costs
   ~200 KB. Proven with `tools/fontprobe.mjs`.
2. **pdf.js segments text items differently in the browser than under Node.**
   `No.Kad` arrives as `N` + `o.Kad`; the trailing `:` is its own item and
   cleans to an empty label. Fixed by joining items using the measured
   horizontal gap, and by keeping reaching left until the cluster is non-empty.
3. **The source PDF was already filled — as annotations.** It carried two
   FreeText annotations (name + IC) and a Stamp annotation (the company stamp).
   Filling on top produced double names and two overlapping stamps. Now
   `stripOverlappingAnnotations()` removes any annotation whose rect overlaps a
   blank being written, and the UI warns about it.
4. **`[hidden]` was overridden** by `.card { display: flex }`. Needs an explicit
   `[hidden] { display: none !important }`.

  2. Signature and stamp were silently dropped on AcroForm PDFs, because a form
     field can only hold text. Now those roles bypass the form path and draw
     onto the widget rect.
  3. `findUnderlines` never matched anything: `constructPath` sub-commands are
     pdf.js *operator codes* (13/14), not 0/1, and the CTM was not being
     tracked. Fixing it then produced five phantom fields on the real template
     (footer rules, table borders, an underlined company name — one of which
     claimed the `company` role). Rules are now gated on width, "no text sitting
     on top", and label shape.
