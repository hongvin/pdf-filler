# 2026-09-19

## Code review of pdf-filler (no changes made)

Read the whole deployed surface (`public/app.js`, `public/lib/*.js`,
`functions/*.js`, `index.html`, `styles.css`, `wrangler.toml`, `README.md`) and
ran the headless harness against the real template + both fixtures. Harness is
green: `QT-2026-307-pact.pdf` → 6 blanks, `fixture-underline.pdf` → 6,
`fixture-acroform.pdf` → 4 in form mode. Vendored pdf.js is 4.6.82, identical
to `node_modules`; pdf-lib 1.17.1.

### Confirmed bug (verified with a hand-built PDF, fix proven)

`detect.js:findUnderlines` never sees rules drawn with the PDF **`re`
operator**. pdf.js emits those as `OPS.constructPath` with a *command list* of
`[OPS.rectangle]`, but the command loop (detect.js:220-236) has no `rectangle`
case and hits `else { break; }`. The separate top-level
`else if (fn === OPS.rectangle …)` branch at detect.js:243 is **dead code** —
pdf.js never emits `OPS.rectangle` as its own op (grepped the bundle: the only
occurrence is inside the canvas renderer's constructPath switch).

Measured: a document with `160 698 340 1 re f` rules and correct labels yields
**0 blanks** with the current code, **2 correct blanks** once the command loop
handles `OPS.rectangle` (push both long edges, `ci += 4`). Word / LibreOffice /
Acrobat all emit rules this way, so this is the common case, not an edge case.
Note pdf-lib's own `drawRectangle` emits moveTo/lineTo/closePath, which is why
the existing `fixture-underline.pdf` passes and hides the bug.

### Other findings (not fixed)

- `roles.js:63-66` + `analyse.js:50-53`: the "offer an extra blank as company"
  rule keys off `role === 'ignore'`, which includes blanks that are *labelled*
  but unrecognised. Verified: a `Jawatan` underline is rewritten to `company`
  whenever the document prints a company name → company name on the wrong line.
  Should require `!b.label`.
- `detect.js:147` sets `kind = 'mixed'` when a dot run and a drawn rule merge
  (Word-style dot leader + bottom border, baselines within 0.45em). `mixed`
  fails both `app.js:488` (`b.kind === 'dots'` → no Clear checkbox) and
  `fill.js:195` (`blank.kind === 'dots'` → no `clearDots`), so printed dots
  stay under the typed value and the user cannot turn it off.
- `stampMode` is never read in `public/lib/` — grep-confirmed dead config.
  Picking "Use a scan" without uploading silently yields a generated stamp.
- `app.js:101-105,286`: `sigImage`/`stampImage` base64 go into `localStorage`
  and `saveSettings` runs on every keystroke; the quota `catch` is silent, so a
  large scan is lost on reload with no warning.
- `app.js:525`: `if (… || state.rendering) return;` drops a re-render requested
  during an in-flight render (role dropdown changes).
- `app.js:342-355`: `state.bytes` is swapped before `state.blanks`; if
  `analyse()` throws, Fill still works and writes the *previous* file's blanks
  onto the new PDF.
- Dead code / drift: `IC_STORE_KEY` written nowhere, `lineKey()` unused,
  `used` set in `assignRoles` write-only. README claims Great Vibes is the
  signature face (default is KaushanScript), lists `tools/dbg-validate.mjs`
  which does not exist, says `fonts/` holds only Great Vibes, and gives
  `STAMP_BOTTOM_TEXT` a default of MALAYSIA (the code draws a star when unset).
- No git repo here, only a `.gitignore` — nothing is under version control.
- `public/_headers` does not apply to Pages Functions responses, so
  `/api/config` ships without `nosniff`; Basic auth has no rate limiting.

## All findings fixed, verified in a real browser (same day, later)

Every item above is now fixed. Details worth keeping:

- **`re` operator** — added an `OPS.rectangle` case to the `constructPath`
  command loop. Coords are `x, y, w, h`; only thin rectangles (`|h| <= 3`)
  become rules, so table cells and panels stay out. Kept the standalone
  `OPS.rectangle` branch as a documented fallback for a pdf.js version bump.
  Measured before/after: **0 blanks → 2** on a hand-built `re` document.
- **New fixture `tools/fixture-rect.pdf`** plus `tools/check-detection.mjs`,
  which asserts 8 behaviours including the negative cases. `fixture-underline`
  did NOT cover this — pdf-lib emits moveTo/lineTo, which is a different branch.
  That is why the bug survived a green test suite.
- **`hasPrintedDots()` / `shouldClearDots()`** exported from `fill.js` so the
  fields table and the writer share one predicate. `mixed` regions now clear.
- **Company hint** now requires `!b.label`. Verified: "Jawatan" stays `ignore`.
- **`NotReadableError`** — found only by driving a real browser. `app.js` cleared
  the file input immediately after calling the async `handleFile`, releasing the
  File's backing store while `arrayBuffer()` was in flight. Now awaited first.
  The headless harness and two full read-throughs had both missed it.
- **Settings** — debounced 250 ms, flushed on `pagehide`, quota failure shows a
  banner, scans over 1.5 MB refused up front. `resetBtn` cancels the pending
  write so it cannot land after the keys are removed.
- **`resetDocumentState()`** runs on Remove and before each new analysis;
  preview renders queue instead of being dropped.
- **Functions** — `nosniff` + `referrer-policy` repeated on Function responses
  (`public/_headers` does not cover them). Verified via `wrangler pages dev`:
  `/` and `/api/config` 401 unauthenticated, 200 authenticated, headers present.
- **Preview/annotation question settled**: `annotationMode: DISABLE` genuinely
  works. DISABLE vs ENABLE renders of the real template differ by ~36k pixels;
  with DISABLE the annotation values vanish while the genuinely printed company
  name stays. Earlier suspicion that the preview leaked stale values was a
  misreading of a low-resolution screenshot.
- **git initialised** (`main`, one initial commit, repo-local identity). Found
  that `.gitignore`'s `node_modules/` did not match the sandbox *symlink* — the
  pattern is now `node_modules` without the trailing slash.

Note for the browser tooling: `agent-browser errors` did not clear with
`--clear` and its list survived `close --all` within one CLI session, which made
a fixed bug look live. Confirm the list is empty on a fresh session *before*
interacting. Also: the sandbox sets `HTTP_PROXY`, so `curl` to 127.0.0.1 needs
`--noproxy '*'`.
